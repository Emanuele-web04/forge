## What changed natively

- An irreversible input gate tracks held mouse/keyboard input and whole action contexts. Matching releases are prepared before down events. Guards release on return, error, cancellation and Rust unwind; delays wake on cancellation. Context leases include native restoration and verification.
- The private `cancel_input` endpoint accepts only the authenticated embedded parent and the exact child PID. Cleanup is acknowledged only after held input and action contexts drain. Native stdin EOF uses the same drain before cancelling connection tasks.
- Synara validates admission closure, zero pending input, cleanup completion and PID. Missing or invalid acknowledgement blocks replacement and does not permit terminating an active generation. Successful cleanup precedes process exit and any replacement. A crash during input retains an uncertain effect and blocks replacement.
- Backend shutdown suspends the GUI host before draining input. Late requests from the server being stopped are refused until an explicit backend start resumes admission. Resume cannot bypass a failed cleanup barrier. This closes a gap where an ordinary reusable Stop alone could allow a late request to start another generation during shutdown.
- Coordinate click/text select synthetic delivery before dispatch. The mouse recipe is chosen from process metadata. Each event is posted through SkyLight, or through the public API only if the private entry point is unavailable before submission. There is no duplicate transport submission or uncertain-action replay.
- The cursor overlay holds one replaceable pending bitmap and at most one queued presentation callback. CoreGraphics takes ownership of the pixels without another full-screen copy. The overlay remains enabled; this does not eliminate its animation CPU cost.

The mouse recipes retain native preparation/primer events. “One click, one effect” means one requested click and one application counter increment, not a claim that the entire native recipe contains only two OS events. The AppKit companion is hosted inside the Electron fixture bundle; framework-based classification and its outside-control primer events do not establish standalone AppKit recipe coverage. No personal app was an input target.

## Real provider and approval UI

Live-provider run 2 used installed fixture revision 9/build 18, GUI PID 99565, native PID 99569 and the same universal artifact. Its real production Synara server used an isolated home and workspace on loopback port 61300. Codex GPT-5.6 Sol made actual Computer tool calls in Ask for approval mode. The browser UI was operated through its visible controls; no provider callback or approval result was fabricated.

A fixture-only socket proxy restricted native inventory, capture and input to `cua:99565:5315`, and admitted at most one unmodified background click inside the owned counter. Five scope preflight refusals passed before provider launch: wrong capability, desktop capture, foreign window, foreground input and clipboard. This qualifies the real provider, UI, gateway and native path under that restriction; it does not qualify the whole-desktop pane or a production signed Synara bundle.

- **Approve once:** the real card displayed the exact window, background delivery, screenshot ID and coordinates. Before approval there were zero native submissions and zero clicks. The persisted acceptance preceded the one native click; the counter became exactly 1. Native uncertainty remained `dispatched-unknown`, and the model used fresh observation without replay. The turn completed.
- **Cancel turn:** a second real card requested a background click on the same counter. Cancelling resolved that request and interrupted its owning turn. Native submissions and counter stayed at 1: the cancelled request never reached the native proxy.
- **Composer persistence:** real use exposed two bugs: draft promotion discarded the explicit Computer choice, and persistence omitted a draft containing only that choice. Both are fixed. The choice survived promotion in the second live turn and a fully hydrated page reload after the final rebuild. Focused tests cover both explicit true and false, ordinary draft clearing and idempotent promotion.

[Native report](evidence/live-provider-report.json), [approval/terminal events and UI observations](evidence/live-provider-approval-events.json), [before](evidence/live-provider-before.png), [after](evidence/live-provider-after.png). The fixture launcher exited with code 0 after SIGTERM; the three exact processes disappeared and the port was released, with no forced native kill.

The model initially interpreted a window's `focused` flag as possible OS foreground activation. That flag actually identifies Synara's selected input target; optional `active` reports native activation, and absence means unknown. Tool guidance now makes this distinction explicit. The UI displayed Low reasoning effort while provider settings events reported medium; this run does not qualify reasoning-effort propagation.

This live-provider fixture build predates the final host suspension change. That change does not alter the native artifact or ordinary turn Stop; its late-request and failed-cleanup cases are covered by the final 12-test host suite, with source-GUI startup/shutdown checked separately. The final foreground/background run 24 includes that host change.

## Resource evidence

Run 21 recorded 53 host samples and 49 native process samples across driver generations 87214, 87726 and 87823. The driver peak was **312.89 MiB**. The earlier unpatched run 8 sampled **3304.23 MiB** and included a foreground action. These differ in action mix, duration and generations; no normalized percentage reduction, steady-state percentile or long-duration leak claim follows from this comparison.

The final run 24 recorded 76 samples across its complete background/foreground suite, with a **307.84 MiB** native driver peak. The sampler now covers up to two minutes so it does not truncate the extra foreground generations. This remains a short fixture observation, not a long-running workload benchmark.

The bounded presentation queue addresses an identified source of accumulated image allocations. Remaining costs include overlay animation and redundant captures for target preparation/native verification. In run 21, Electron click took 2919.42 ms, AppKit click 2819.03 ms, and single-window text about 1.26–1.27 s. No matching Swift measurements exist.
