# Slice E — E2E-encrypted Host Secrets sync

**Draft — finalized after Slice D lands.** Implements workstream E per ADR 0004 (and the device-removal hook from ADR 0015). Touches `apps/api`, `packages/shared`, `apps/desktop`/`apps/web`.

## 1. What syncs

Per-host configuration the *owner's* devices share: SSH destination, launcher config, host-key verification policy. Never private keys in plaintext, never anything an org-mate should see — **Host Secrets never cross user boundaries**, which is why SSH is an owner-only transport (ADR 0004/0013).

## 2. Crypto

- **Sync Key**: 256-bit random, generated by the owner's first device. Cloud never sees it.
- **Envelope**: XChaCha20-Poly1305 (or AES-256-GCM where WebCrypto is the only option) over a JSON blob, per host. Random nonce per write; AAD binds `{hostId, ownerUserId, version}` so a ciphertext cannot be replayed onto another host row.
- **Key delivery on pairing**: the new device generates an ephemeral X25519 (or ECDH P-256) keypair; the existing device wraps the Sync Key to it after the user confirms a short verification code shown on both devices (guards against a hostile pairing prompt). No cloud-side escrow.
- **Rotation on device removal** (ADR 0015): a surviving device generates a new Sync Key, re-encrypts every Host Secret at `version+1`, and uploads atomically. The removed device's cached ciphertexts stay readable but future writes are opaque to it.

## 3. API surface (`apps/api`)

New table `host_secrets`: `host_id` (PK, no FK — mirrors `revocation_events` so deletion order never destroys data), `owner_user_id`, `ciphertext bytea`, `nonce bytea`, `version integer`, `updated_at`, plus a small `host_secret_versions` history table (last N versions) for recovery from a bad write.

- `GET /hosts/:id/secrets` — owner-session only; returns ciphertext + version.
- `PUT /hosts/:id/secrets` — owner-session only; **compare-and-swap on version** (409 on stale) so a rotation and a concurrent edit cannot silently clobber each other. Last-write-wins whole-blob is the resolution rule (ADR: config edits are rare and single-user), but CAS makes the loss visible rather than silent.
- `GET/PUT /sync-key-wraps` — the pairing envelope exchange (wrapped Sync Key per device, delivered once, deleted after retrieval).

The API is deliberately incapable of reading any of it: it stores opaque bytes and enforces only ownership and versioning.

## 4. Client integration

- Desktop reads Host Secrets to populate SSH connection config for hosts it owns; a second Desktop gets working SSH without re-entering anything.
- Losing **all** devices loses the secrets (documented, expected): hosts stay registered and reachable via relay/LAN, the user re-enters SSH config once.
- Web clients hold the Sync Key too (non-extractable-adjacent: stored in IndexedDB, wrapped by a non-extractable WebCrypto key) but have no SSH transport, so they read-only unless the user edits config there.

## 5. Tests

`apps/api`: ownership enforcement (org-mate is 404, not 403 — same opacity rule as hosts), CAS/version conflicts, history retention, ciphertext opacity (the API never decodes). `packages/shared`: envelope round-trip, AAD binding rejects a ciphertext moved to another hostId, rotation re-encrypts every host, wrap/unwrap on pairing, verification-code mismatch aborts. Integration: two simulated devices pair, share a secret, rotate after removal, and the removed device's key no longer decrypts new writes.

## 6. Out of scope

Org-shared secrets (explicitly rejected — see spec "Out of scope"); cloud escrow/recovery; secrets for hosts the user does not own.
