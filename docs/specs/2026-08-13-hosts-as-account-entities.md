# Hosts as First-Class Account Entities

**Status: agreed direction (grilling session 2026-08-13, revised same day after comparing against t3code's production architecture).** Supersedes `2026-08-03-account-backend-design.md` where they conflict. The _why_ behind each decision lives in `docs/adr/0001`–`0009`; vocabulary in `/CONTEXT.md`. This document is the _what_: the model, the services, and the build order.

## Summary

A host is a user's machine running a Synara server, registered on their account and synced to all their devices. Clients (Desktop, iOS, web) reach any host over the cheapest working transport — loopback, LAN, Tailscale, SSH (desktop-only), or the cloud relay. The cloud is a directory + pipe: it stores identity, endpoints, presence, and E2E-encrypted config; hosts own all session state.

## Domain model

- **Host = Environment, 1:1** (ADR 0001). Identity is the environment id. No multi-env-per-machine, no hierarchy. Machine info (hostname, platform, appVersion) is metadata.
- **User-owned** (ADR 0002). `ownerUserId` is the authorization key; org is tenancy. Per-host **discoverability** toggle, **on by default**: on ⇒ the whole org sees _and can use_ the host (visible = usable, no finer grants). The host follows the owner — leaving the org / deleting the account removes or revokes it; no transfer flow.
- **Reachability is attempt-based** (ADR 0010, supersedes 0005/0009). No presence store, no push channel, no client control socket: the probe race is the reachability check, plus an on-demand health call. The host still keeps a supervisor-kept relay control socket — for splice signaling, not presence.
- **Host Keypair** (ADR 0011, 0012): Ed25519, generated at registration, public key in the directory (link proven by signed challenge, nonce-protected). It is the host's **only** credential — the `synhost_` bearer token is removed, host↔API auth is by signature, revocation = deleting the public key. **Hard cutover**: existing deployed hosts are force re-linked; no dual-path auth era.
- **Enrollment** (ADR 0015): three paths into the same link challenge — Desktop sign-in auto-registers the bundled host (primary; multi-member orgs prompt before discoverable, ADR 0002), Desktop SSH bootstrap seeds it, and a device-code flow covers headless boxes. Sign-out unlinks (fresh keypair on next sign-in); device removal revokes the device key, kills its sessions, and rotates the Sync Key.
- **Session Credential** (ADR 0013): minted by the host, DPoP-bound to the client's device key (non-exportable, platform keystore), ~1h TTL, re-mint via fresh grant. **Transport-independent** — same credential over relay, LAN, Tailscale, SSH-forward; mint handshake runs over any transport (grant verified against API keys); loopback/same-machine keeps local trust. SSH port-forwards are _not_ loopback and require the credential.
- **Revocation** (ADR 0013): discoverability-off / org-departure / device-removal kills live sessions — API pushes down the host's control socket, host re-verifies and drops; TTL is the backstop; offline hosts enforce on reconnect.
- **Host Secrets** (ADR 0004): SSH destination, launcher config, key-verification policy — synced across the _owner's_ devices only, E2E encrypted with a **Sync Key** (generated by the first device, passed device-to-device during pairing; cloud stores ciphertext only). Versioned whole-blob, last-write-wins, small version history for recovery. Losing all devices loses secrets, never hosts. Consequence: **SSH is an owner-only transport**; org members use relay/LAN/Tailscale.

## Transports (ADR 0003, 0007)

SSH direct and the relay **coexist**. Selection is client-side: probe candidates concurrently, pick by fixed order **loopback > LAN > Tailscale > SSH (desktop only) > relay**, short-timeout race, no cloud involvement. Candidates come from:

- **Endpoints** the host self-reports to the directory (LAN, Tailscale URLs) — treated as probe candidates; stale entries are harmless. Hosts additionally advertise via mDNS/Bonjour for same-network discovery.
- **The relay**, always a candidate — not an endpoint row; there is one relay per deployment.
- **SSH config** from the owner's Host Secrets (desktop only).

Invariant preserved with one sharpening: loopback/same-machine is local trust and never touches the cloud; already-minted credentials keep working over direct transports through cloud outages until TTL; only a _brand-new_ device→host pairing waits for the cloud. Remote clients are native shells — Desktop and iOS; the relay never serves UI or HTTP (ADR 0014).

## Relay (ADR 0006, 0008, 0010, 0011)

Separate stateless Railway service (`relay.*`), sharing token/schema code via a monorepo package. We keep the data plane on our own infrastructure — a control-plane-only relay provisioning Cloudflare Tunnels (t3code's model) was considered and rejected (ADR 0008).

- **Splice authorization**: client fetches a **Relay Grant** from the API — short-lived (~60s), single-use, host-scoped, signed. API applies the rule (owner, or discoverable + same org); relay verifies signature/host/expiry statelessly, no DB.
- **Session credential**: minted by the **host**, not the cloud (ADR 0011). On splice, the relay forwards a short-lived client-bound mint request; the host verifies it against directory keys and mints the credential the client actually uses.
- **Splice**: 1:1, one data socket per session. Client presents grant → relay signals the host's control socket → host dials a fresh data socket → relay splices. Spliced traffic is opaque end-to-end (the normal Synara WS protocol).
- **Control channel**: hosts hold a supervisor-kept control socket for splice signaling. Clients hold none. "Dumb pipe" applies to spliced data; the host control socket speaks the small relay protocol.

## Cloud data (delta from current `apps/api` schema)

`hosts`: add `ownerUserId` (authz key), `discoverable boolean default true`, `publicKey` (Ed25519, set at link); keep unique `(ownerOrgId, environmentId)`; drop `"public"` from endpoint transports (relay is not an endpoint), keep `lan | tailscale`; endpoints reported at startup/on-change, full-replace, no TTL. **Drop `hostTokens` entirely** (ADR 0012 — keypair is the credential; hard cutover, existing hosts re-link). New: `hostSecrets` (ciphertext blob per host, versioned LWW, owner-readable only), `devices` (device key registry per user). No presence columns beyond `lastSeenAt` (ADR 0010). Route authz shifts from org-membership to owner-or-(discoverable ∧ same-org).

## Workstreams & build order

Thin vertical slice first — prove the riskiest path (client → relay → host) end to end before polish:

1. **A — Account API**: owner-scoped hosts + discoverability; keypair link challenge replacing `hostTokens` (hard cutover); device key registry; grant issuance endpoint; owner-aware route authz; revocation push hooks. (Independently landable.)
2. **B — Relay service**: control protocol, grant verification, mint-request forwarding, revocation signal delivery, 1:1 splice. Minimal.
3. **C — Host relay dial**: supervisor-kept control socket in `apps/server`, transport-independent mint endpoint, session kill on revocation signal, data-socket dial on splice signal.
4. _Slice checkpoint: a client opens a real session through the relay, zero UX polish._
5. **D — Clients**: device keypair in platform keystore, transport probe/race + DPoP credential reuse across transports, host list with attempt-based reachability, mDNS advertise/discover, Desktop sign-in auto-register + sign-out unlink + multi-member-org prompt, headless device-code flow.
6. **E — Secrets sync**: Sync Key exchange during device pairing, hostSecrets ciphertext CRUD (versioned LWW), Sync Key rotation on device removal, SSH-from-second-desktop.

`feat/remote-hosts-combined` is a **reference implementation**, re-landed piecewise as the spec dictates: connectivity state machine, probe logic, and SSH bootstrap pipeline likely survive largely intact; the `/env/:envId` proxy is re-examined once the relay exists.

## Out of scope (deliberate no-s)

Multi-env-per-machine; per-user access grants; org-owned hosts or ownership transfer; multiple/regional relays; relay opt-out; stored/pushed presence and live online dots (attempt-based only, ADR 0010); org-shared SSH secrets; session multiplexing over one relay socket; Cloudflare-Tunnel-style provisioned data plane.
