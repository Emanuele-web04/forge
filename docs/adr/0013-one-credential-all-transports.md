# One session credential across all transports; revocation is pushed; loopback stays local-trust

The host-minted, DPoP-bound session credential (ADR 0011) is transport-independent: the same credential authenticates the client over relay, LAN, Tailscale, or SSH port-forward, so the probe race can switch transports mid-session without re-auth. Grant+mint is only how a client *first* obtains it (requires the cloud); afterwards direct transports work offline until TTL. Exception: loopback/same-machine keeps the existing local trust path — the primary desktop experience never depends on the cloud. Rejected: relay-only minting with direct transports on legacy pairing auth (two parallel auth models, re-auth on transport switch).

Minting is likewise transport-independent: the mint endpoint is part of the host's own protocol. A client presents its API-issued grant directly over whatever connection it has (LAN, Tailscale); the host verifies the grant against the API's published keys and mints. The relay's mint-request forwarding is just the transport-specific carrier of the same handshake. SSH port-forwards are *not* loopback: the server distinguishes forwarded connections and requires the credential — local trust is for same-machine processes only.

Revocation (kill live sessions, per discoverability-off or org departure): the API pushes a revocation signal down the host's always-connected relay control socket; the host re-verifies affected sessions against the API and drops them — covering direct sessions that never touched the relay. Offline hosts pick the change up on reconnect; the ~1h credential TTL is the backstop.

Client device keypairs live in the platform keystore (Secure Enclave / Keychain / TPM / non-extractable WebCrypto), non-exportable where the platform allows; the device key is the device's identity on the account, registered at sign-in/pairing (the same pairing that hands over the Sync Key). Accepted trade-off of no offline enrollment: a brand-new device→host pairing waits for the cloud; existing credentials keep working over LAN through outages.
