## Objective

A user in any project chat opens the composer "+" menu, picks "Attach issue or PR", searches the current project's GitHub repo (or browses a recently-updated default list), and attaches up to 5 issue/PR chips. Sending serializes a snapshot of each item (kind, number, title, state, URL, ≤500-char body excerpt) into the outgoing message text so ANY provider agent gets the context with zero network access. The URL lets `gh`-capable agents fetch more.

## Data shape

A `WorkItemAttachment` (or `ComposerWorkItemAttachment`) represents one attached issue or pull request.

- `kind`: `"issue" | "pull-request"`
- `number`: positive integer
- `title`: non-empty string
- `state`: `"open" | "closed" | "merged"`
- `url`: non-empty string
- `bodyExcerpt`: string, max 500 chars
- Stable `id` for the attachment draft (e.g. random UUID)
- `createdAt` and `updatedAt` are ISO strings; `updatedAt` is what the list/search results report and is used to rank the default "recently updated" list.

A `WorkItemSnapshot` is the wire/contract type (the fields that travel in the `<attached_work_items>` block). It is the same minus the draft id/createdAt. Use the contract schemas in `packages/contracts/src/workItems.ts` for both.

## Server-side behavior

1. Add a new `WorkItemSearchInput` and `WorkItemSearchResult` to `packages/contracts/src/workItems.ts`:
   - `WorkItemSearchInput`: `cwd` (string), `query` (string, optional), `limit` (number, default 20, max 20).
   - `WorkItemSearchResult`: `available` (boolean), `errorHint` (string | null), `items` (WorkItemAttachment array).
   - `WorkItemAttachment` contract type with the fields above.
2. Export the new schemas from `packages/contracts/src/index.ts`.
3. Add a WebSocket method `workItemsSearch` to `packages/contracts/src/ws.ts`.
4. Add the matching `WsWorkItemsSearchRpc` to `packages/contracts/src/rpc.ts`.
5. Add the matching method to `packages/contracts/src/ipc.ts` if the `NativeApi` interface is defined there; otherwise ensure the type is exported and `apps/web/src/wsNativeApi.ts` can wire it.
6. In `apps/server/src/wsRpc.ts`, add a handler for `WS_METHODS.workItemsSearch`.
7. Implement the search by delegating to the existing `GitHubCli` and `PullRequestService`.

The search must be read-only, use `gh` (GitHub CLI), and support two modes:

- Empty query: list the most recently updated open issues and PRs for the repository. Return up to 20 items, sorted by `updatedAt` descending. You may implement this with `gh issue list --json number,title,state,url,body,updatedAt --state open --limit 20` and `gh pr list --json number,title,state,url,body,updatedAt --state open --limit 20`, merge both, truncate body to 500 chars, and return the top 20 by `updatedAt`.
- Non-empty query: `gh search issues --json number,title,state,url,body,updatedAt --repo <owner/repo> "<query>" --limit 20` and `gh search prs --json ... --repo <owner/repo> "<query>" --limit 20`, merge, truncate body, top 20.

The repository must be resolved from `cwd` using the existing `resolveGitHubRepository` helper (or equivalent), which reads the GitHub remote.

If `gh` is not authenticated, return `available: false` and `errorHint: "GitHub CLI is not authenticated. Run 'gh auth login' and retry."` (or the existing localized message). If `gh` is not installed, `available: false` with a not-installed hint. If the repo has no GitHub remote or no results, `available: true` and `items: []`. Never crash.
